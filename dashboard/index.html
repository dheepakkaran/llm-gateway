Questions

What does the guard check?

In order, cheapest first: the global kill switch, the agent's key, whether the agent is suspended or killed, prompt size (token bomb), requests per minute, the same prompt repeated more than 5 times in 2 minutes, 10 failed or blocked calls in 1 minute (retry storm), tokens per minute, and the daily token budget. Only then does the request go to a model, with automatic fallback to a second provider.

Why does this cost $0?

It runs only on AWS always-free services: Lambda with Function URLs instead of API Gateway, DynamoDB in provisioned mode within 25 read and 25 write units, SSM Parameter Store for secrets instead of Secrets Manager, and EventBridge Scheduler. The demo uses a mock model, and the real providers (Groq, Gemini) are on free tiers. Demo runs are rate-limited for every visitor together.

What happens to a real agent that gets suspended?

It is blocked for 15 minutes and its owner gets a Telegram alert with the rule that fired, the evidence, and the calls blocked. After the cooldown it works again on its next request. If it trips again within 24 hours it is killed and stays off until an admin resumes it. Demo agents use a 2-minute cooldown and never alert.

What if a good agent gets blocked by mistake?

An admin can resume it instantly from Telegram (/resume agent-id) or the admin API, which also clears its violation history. Limits are set per agent, so an agent that legitimately repeats a prompt or runs fast gets higher limits. The normal-agent stage of the demo measures false blocks on every run.

What data does the demo use?

Questions sampled from databricks-dolly-15k (CC BY-SA 3.0), human-written instructions. The demo sends them to a mock model, so no real model is called and no prompt text is ever shown here or stored in logs.
